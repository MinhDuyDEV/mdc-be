## SCHEMA OVERVIEW

### Models

- **User** — Authentication principal. Fields: id (UUID), email (unique), passwordHash (optional), emailVerifiedAt, status (enum: ACTIVE/DISABLED/DELETED), timestamps. Relations: refreshTokens (1:N), auditLogs (1:N).
- **RefreshToken** — OAuth/session tokens. Fields: id, userId (FK), tokenHash (unique), expiresAt, revokedAt, timestamps. Indexes on userId and expiresAt for efficient token lookup and expiry cleanup.
- **AuditLog** — Event audit trail. Fields: id, actorUserId (FK, nullable), action, entityType, entityId, metadata (JSON), ip, userAgent, createdAt. Indexes on actorUserId, (entityType, entityId), action, createdAt for querying audit history.
- **OutboxEvent** — Transactional outbox for event sourcing. Fields: id, eventType, aggregateType, aggregateId, payload (JSON), status (enum: PENDING/PROCESSING/PROCESSED/FAILED), attempts, availableAt, lockedAt, lockedBy, processedAt, timestamps. Relation: deadLetter (1:1). Indexes on (status, availableAt) for polling, (aggregateType, aggregateId) for aggregate queries, eventType for filtering.
- **OutboxDeadLetter** — Failed event storage. Fields: id, outboxEventId (FK, unique, nullable), eventType, payload (JSON), reason, failedAt. Indexes on eventType and failedAt for dead-letter analysis.
- **IdempotencyKey** — Request deduplication. Fields: id, scope, key, requestHash, responseStatus, responseBody (JSON), expiresAt, timestamps. Unique constraint on (scope, key); index on expiresAt for cleanup.

## AI AGENT INSTRUCTIONS

### When Modifying the Schema

1. **Edit `schema.prisma`** — Add/modify models, enums, relations, or field attributes.
2. **Generate migration** — Run `npx prisma migrate dev --name <description>` to create a timestamped migration file in `migrations/`.
3. **Review migration SQL** — Inspect the generated `.sql` file to ensure correctness (indexes, constraints, data transformations).
4. **Test locally** — Run migrations against a local PostgreSQL instance before committing.
5. **Commit both** — Always commit `schema.prisma` + the new migration folder together.

### When Adding a New Model

- Use UUID primary keys: `@id @default(dbgenerated("gen_random_uuid()")) @db.Uuid`
- Map field names to snake_case in the database: `@map("field_name")`
- Add timestamps: `createdAt DateTime @default(now())` and `updatedAt DateTime @updatedAt`
- Add indexes for foreign keys and frequently queried fields: `@@index([fieldName])`
- Document the model's purpose in a comment above the model definition.

### When Adding a Relation

- Use explicit foreign key fields: `userId String @map("user_id") @db.Uuid`
- Define the relation: `user User @relation(fields: [userId], references: [id], onDelete: Cascade)`
- Add an index on the foreign key for query performance.
- Consider cascade/set-null delete behavior based on domain semantics.

### When Querying Data

- Use Prisma Client (auto-generated from schema): `import { PrismaClient } from '@prisma/client'`
- Leverage indexes: filter by indexed fields (status, eventType, createdAt, etc.) for efficient queries.
- Use `select` or `include` to control which fields/relations are fetched.
- For bulk operations, use `createMany`, `updateMany`, `deleteMany` with caution (test in dev first).

### When Debugging Schema Issues

- Run `npx prisma db push` to sync schema to database without generating a migration (dev only).
- Run `npx prisma studio` to open a GUI for browsing and editing data.
- Check `_prisma_migrations` table to see applied migrations.
- If a migration fails, inspect the error, fix `schema.prisma`, and run `npx prisma migrate resolve --rolled-back <migration-name>` to mark it as rolled back, then create a new migration.

## COMMON PATTERNS

### Transactional Outbox (Event Sourcing)

The `OutboxEvent` + `OutboxDeadLetter` models implement the transactional outbox pattern:

1. Write domain event to `OutboxEvent` in the same transaction as the business operation.
2. A background worker polls `OutboxEvent` where `status = PENDING` and `availableAt <= now()`.
3. Worker locks the event (`lockedAt`, `lockedBy`), publishes it, and updates `status = PROCESSED`.
4. If publishing fails after max retries, move to `OutboxDeadLetter` for manual inspection.

### Idempotency

The `IdempotencyKey` model prevents duplicate processing:

1. Client sends a request with an idempotency key (e.g., UUID).
2. Server checks `IdempotencyKey` for (scope, key) match.
3. If found and not expired, return cached response.
4. If not found, process request, store result in `IdempotencyKey`, return response.
5. Cleanup: delete expired keys periodically.

### Audit Logging

The `AuditLog` model tracks all significant actions:

1. After a domain operation, insert an `AuditLog` record with action, entityType, entityId, metadata, and actor info.
2. Query audit history by entityType/entityId or by actor for compliance/debugging.
3. Indexes on (entityType, entityId) and createdAt enable efficient range queries.

## GOTCHAS

- **Migrations are immutable** — Once committed and deployed, never edit a migration file. Create a new migration instead.
- **UUID generation** — Use `@default(dbgenerated("gen_random_uuid()"))` for PostgreSQL; Prisma Client cannot generate UUIDs in JavaScript.
- **Enum changes** — Adding enum values is safe; removing or renaming requires a migration that handles existing data.
- **Relation cascades** — `onDelete: Cascade` deletes related records; use `onDelete: SetNull` to preserve history.
- **JSON fields** — `Json` type stores arbitrary JSON; validate structure in application code, not the database.
- **Index naming** — Prisma auto-generates index names; be explicit with `@@index([field], name: "idx_custom_name")` if needed for clarity.
